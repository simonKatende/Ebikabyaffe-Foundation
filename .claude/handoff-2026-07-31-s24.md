## 1. Business Owners directory + Bataka Panel review workflow

**The ask, in two parts across two turns**: (a) let members advertise a business/organisation from their profile, with a "Business Owners" link on the logged-in home tab to browse what's posted; (b) require every listing to be verified by clan officials — who may contact the owner for confirmation/proof of business — before it reaches other members.

- **`web/lib/businesses/`** (`types.ts`, `store.ts`, `mockBusinesses.ts`) — a `BusinessListing` has a `status: "pending" | "info_requested" | "verified" | "declined"` lifecycle, mirroring `PanelMember`'s shape in `lib/batakaPanel/types.ts` exactly. One listing per member (keyed by phone, same identity key as `lib/auth/registry.ts`). `upsertListing` always resets status to `"pending"` on any (re)submission — editing live content doesn't bypass review. `visibleListings()` (only `status==="verified"`) is what the public directory reads; `listingsForReviewer()` is the clan/admin-scoped selector the panel uses. 5 seed listings pre-verified, 1 seed (`Mukasa Motor Spares`, Mmamba) left pending so the review-queue demo isn't empty.
- **`components/profile/BusinessListingCard.tsx`** (on `/profile`) — the posting form: name, category, description, contact phone/email, location, and a photo (`FileReader` → data URL, no upload backend). Shows the member their own listing's status regardless of state, with the officer's note surfaced verbatim when `info_requested`/`declined`.
- **`app/businesses/page.tsx` + `components/businesses/BusinessDirectory.tsx`** — public directory (no login needed to browse), search + category filter chips, each card links to the owner's clan page.
- **`components/home/HomeDashboard.tsx`** — new "🏪 Business Owners" card: "Browse Business Owners →" always shown, plus a status-aware second line/button ("List your business" / "awaiting review" / "info requested" / "declined" / "is live").
- **Officer review — reused the *existing* Bataka Panel rather than building a parallel system**: new `app/batakaPanel/businesses/page.tsx` (list, filterable by status) + `app/batakaPanel/businesses/[id]/page.tsx` (detail + **Verify / Request confirmation-or-proof-of-business / Decline**, same three-action pattern as member-verification). `PanelShell.tsx` gained a "Business Listings" tab. `app/batakaPanel/page.tsx`'s dashboard gained a "Business Listings Awaiting Review" queue card alongside the existing member queue.
- **Shared audit trail**: `lib/batakaPanel/store.ts` gained an exported `logExternalAction(clanSlug, action)` so business-review decisions append to the *same* "Recent Panel Activity" feed as member-verification actions — one unified log per officer, not two separate ones. (This is a deliberate cross-store call, matching the precedent of `recordVerification()` already being called from inside `batakaPanel/store.ts`.)
- Verified end-to-end with Playwright, including the review actions (verify/decline/request-info) and the shared audit trail entry appearing correctly. One real bug caught and fixed mid-build: `VerificationCard` and `BusinessListingCard` were both keyed `key={clan.slug}` as siblings in `ProfileContent.tsx` — a real duplicate-React-key warning, fixed with distinct prefixed keys (`verification-${slug}` / `business-${slug}`).

## 4. Login flow — full redesign, permanent clan attachment, redirect fix

Several rounds of changes to `components/auth/LoginFlow.tsx`, all on top of the pre-existing (previously "ask the user" flagged, now fully owned) diaspora/26-country phone code:

- **Visual redesign**: split branding-panel + form-card layout (green gradient + decorative circles on the left, pill-style inputs with person/phone icons on the right), modeled on a reference image the user supplied, reusing the site's own green/gold palette rather than the reference's blue.
- **Real bug fixed — phone digit limits weren't per-country**: added `minDigits`/`maxDigits` per country (Uganda stays its exact 9-digit rule; UK/US/India=10, China=11, Qatar/Norway/Denmark=8, etc.), enforced via both `maxLength` on the input and `normalizeNational()`.
- **Real bug fixed — country flag wasn't reliably visible**: native `<select>` option rendering is OS-drawn (not the page's own font stack), and Windows often falls back to plain "UG"-style text instead of an actual flag glyph inside the dropdown. Fixed by rendering the selected country's flag as its own `<span>` *outside* the native select box, guaranteed to use the page's normal text/emoji rendering.
- **Account creation now redirects to `/` (home), not `/profile`** — sign-in still goes to `/profile` as before (only create-mode changed, per explicit request).
- **Clan attachment is now permanent**: `ProfileContent.tsx`'s clan card shows a locked notice ("Your clan is set for good... contact the Foundation") with no picker once `user.clanSlug` is set — the picker only reappears in the (rare, mock-only) case of no clan at all, as an escape hatch for the sign-in flow's known limitation (it doesn't restore a returning member's clan).
- **Real bug fixed (this session's own bug-sweep, see §7) — logged-in members clicking "Join the {clan} clan" on any clan page were bounced to the create-account flow even though they already have a clan.** New shared hook `lib/useJoinClan.ts`: if not logged in, proceeds to `/login?clan=<slug>` as before (genuine new-account path); if logged in and already in that clan, toasts "You're already a member of the X clan"; if logged in and attached to a *different* clan, toasts "You can't join this clan since you're already attached to the X clan" and does **not** navigate anywhere. Wired into all three clan detail components (`GenericClanDetail`, `MmambaDetail`, `LugaveDetail`), both their top and bottom "Join" buttons.

## 5. Profile picture upload

`ProfileContent.tsx` (identity card) and `Nav.tsx` (top-right avatar) now show a member's own uploaded photo once set, falling back to initials otherwise (`AppUser` gained `avatarDataUrl?: string`). Investigated a user report of "I tried to upload a photo but it can't" — traced conclusively (via direct FileReader/Image-state instrumentation, not guessing) to the *lack of any error handling*, most likely triggered by an iPhone HEIC photo: HEIC reads into a data URL fine but most browsers can't decode it in an `<img>`, leaving a silent blank circle with zero explanation. Fixed via a new shared `lib/photoUpload.ts` (`readPhotoAsDataUrl()`): rejects unsupported formats/oversized files (>8MB) upfront with a clear toast, plus an `onError` fallback on every avatar/photo `<Image>` as a second safety net. Applied to both `ProfileContent.tsx` and `BusinessListingCard.tsx` (same gap existed there).

## 7. Bug sweep + responsive audit (2 parallel subagents)

Dispatched one general-purpose subagent for a codebase-wide logic bug sweep and one for a Playwright-driven responsive audit across every route at mobile/tablet/desktop widths — both report-only (no edits), fixes applied centrally afterward and independently re-verified before accepting.

**Bug sweep found 3 real issues, all fixed:**
- `/give`'s Sacco `saccoStats` data was fully deleted (not just hidden) when the visible donation tile was removed (§6), silently breaking the `?option=donation` deep link used by 3 CTAs (`HomeLanding.tsx` ×2, `ProfileContent.tsx`) — they'd land on a bare amount picker instead of the intended "Contributing to: Donations" guided view. Fixed by restoring just the underlying data (needed for the deep-link preset match) while keeping the visible tile removed, per the original request.
- The country `<select>`'s `onChange` reset OTP state on country change but not the phone number itself — switching countries mid-entry silently reinterpreted already-typed digits under the new country's dial code with no warning, capable of minting the wrong E.164 identity. Fixed by clearing `phoneRaw` too.
- A stale code comment in `HomeDashboard.tsx` still described the old mailto: behavior after §3's Resend rebuild — corrected.

**Responsive audit found 2 real issues, both fixed:**
- **`Nav.tsx`'s desktop tab row broke at exactly tablet width.** The `md:` (768px) breakpoint activated the full 7-tab row, but it doesn't actually fit until ~1280px (measured directly: 851px of content needed, only 705px available at 1024px/`lg:`; fits with *zero* spare margin at 1280px). Tab labels were clipping mid-word with no scrollbar/fade/arrow to indicate more content existed. Fixed by moving the hamburger-menu/full-row breakpoint from `md:` to `xl:` (1280px) throughout — the hamburger already rendered cleanly at every width per the same audit, so it now covers the entire tablet range instead of silently truncating.
- **Wide data tables on `/kabaka` and `/abakungu` were unreadable at mobile width before scrolling.** They were already correctly wrapped in `overflow-x-auto` (no page-level overflow), but with no `min-width` on the `<table>` itself, the browser squeezed columns down to ~90px with single-word-per-line wrapping, and there was no visual hint that more content existed off-screen. Fixed by giving every table (`KabakaContent.tsx` ×2, `AbakunguContent.tsx` ×6) a `min-w-[...]` sized to its own column count/content (600–760px), so columns stay readable and the table becomes properly horizontally scrollable instead of squished, plus a `sm:hidden` "← Swipe to see more →" hint above each one.

Both subagents' scratch scripts/screenshots were cleaned up (none left in `web/`). `tsc`/`eslint`/`npm run build` (75 pages) all clean after every fix.
