## Cross-tab sync (`lib/crossTabSync.ts`, new)

User reported: registering as a member in one browser tab and reviewing in the panel in another tab (no reload) showed nothing — because every mock store here is a plain module-level JS variable, and each browser tab runs its own independent copy with no backend behind it. Root-caused and fixed with a deliberate, acknowledged stopgap (**not** real persistence — a hard reload, incognito, or different browser still resets to seed data):

- **`saveSynced(name, value)`** — writes to `localStorage` under a prefixed key.
- **`readSynced(name)`** — reads it back.
- **`onExternalSyncChange(name, cb)`** — fires `cb` on the native `storage` event (which, per spec, only ever fires in *other* tabs, never the one that wrote it).
- **`withCrossTabSync(name, baseSubscribe, apply)`** — wraps a `useSyncExternalStore`-based store's `subscribe` function so that (a) the moment anything subscribes it catches up with whatever another tab last wrote, and (b) live updates apply from then on. **This is timing-safe for SSR/hydration on purpose**: React only calls a store's `subscribe` *after* the first commit, never during the render that produces the initial/hydrated output, so applying a different value there cannot cause a hydration mismatch — reading `localStorage` at module-init time instead *would* have (this codebase's seed data is deliberately deterministic specifically to avoid that class of bug — don't undo that by reading synced state before first paint).

Wired into:
- `lib/businesses/store.ts` — the actual scenario reported (`SYNC_NAME = "businesses"`).
- `lib/batakaPanel/store.ts` — only `{members, audit, announcements}` sync (`SYNC_NAME = "panel-data"`); **`session` is deliberately excluded** — each tab keeps its own signed-in identity, so one tab can stay a member while another is the officer/admin, watching live. This is the whole reason the sync is scoped this way — don't widen it to include `session`.
- `lib/stats.ts` — the registered/verified counters and per-clan deltas (`SYNC_NAME = "stats"`).
- `lib/auth/registry.ts` — the phone→name `Map` (not `useSyncExternalStore`-based; serialized as a `[phone, name][]` array, merged into the `Map` on every read plus a live `storage` listener).

Verified end-to-end with two Playwright pages in one browser context: admin panel already open in tab B, member account created + business listing submitted in tab A, appeared live in tab B's queue with zero reload.

## Member-facing fixes and additions

- **Real bug — profile picture lost after logout.** Root cause (found via scripted repro, not guessed): `ProfileContent.tsx`'s photo upload only updated local component state; it required a separate, unrelated "Save changes" click to actually persist via `updateUser`. Since the photo preview already *looked* saved the instant it was picked, a member who uploaded and then signed out without noticing that button lost it. Fixed: `handlePhotoChange` now calls `updateUser({avatarDataUrl})` immediately, with a "Profile picture updated." toast; the broken-image `onError` fallback also now clears the stored value, not just local state.
- **Real bug — sign-in redirected to `/profile`, sign-up redirected to `/`.** Inconsistent and reported by the user as "I want it to still be the dashboard page." `LoginFlow.tsx`'s post-OTP `router.push(mode === "create" ? "/" : "/profile")` is now unconditionally `router.push("/")` for both paths.
- **Name fields strip spaces.** Surname/First name/Given name inputs in `LoginFlow.tsx` now run `stripSpaces()` (removes all whitespace) on every keystroke, so typing "Simon Katende" into Surname produces the garbled "SimonKatende" rather than silently accepting two names in one field — makes the mistake obvious instead of masking it.
- **Custom country-code picker.** Replaced the native `<select>` in `LoginFlow.tsx` with a custom button+dropdown: collapsed shows just flag+dial-code (e.g. "🇬🇧 +44"), click opens a scrollable list of all 27 countries (flag + full name + dial code), selecting collapses it back down. Closes on outside click or Escape (same pattern as `Nav.tsx`'s `MobileMenu`). **Note:** in this dev environment's Playwright/Windows Chromium, flag emoji render as two-letter fallback text ("UG", "GB") rather than actual flags — confirmed this is a pre-existing, environment-wide font limitation (Nav's own "🇬🇧 EN" language toggle shows the same fallback in screenshots taken this session), not a regression; real browsers with proper emoji fonts render the actual flags.
- **`components/home/MemberTabs.tsx`** (new) — a small "🏠 Dashboard / 👤 Profile" pill toggle rendered at the top of both `HomeDashboard.tsx` and `ProfileContent.tsx`'s logged-in view, mirroring the Bataka Panel's own tab-bar idea so a member can flip between their two "home base" pages without going through the full main nav.
